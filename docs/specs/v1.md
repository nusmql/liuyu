# Voice Input Method for macOS - Product Requirements Document

**Version:** 1.0  
**Platform:** macOS 13.0+ (Apple Silicon optimized)  
**Date:** February 2025  
**Status:** Draft

---

## 1. Executive Summary

A system-wide voice-to-text input method that allows users to dictate text into any application using a hold-to-talk paradigm. The application provides a minimal, floating interface for recording and transcription management, with deep integration into the macOS ecosystem via global hotkeys and clipboard automation.

---

## 2. Objectives & Success Criteria

**Primary Objective:**  
Enable hands-free text input across all macOS applications with minimal friction (sub-3-second latency from speech to clipboard).

**Success Metrics:**
- Latency: &lt; 3s end-to-end (release key to text in clipboard)
- Accuracy: &gt; 95% transcription accuracy for English/Mandarin in quiet environments
- Accessibility: System-wide functionality regardless of active application
- Reliability: &lt; 1% crash rate, graceful handling of API failures

---

## 3. User Stories

**As a** content creator,  
**I want to** dictate text while my hands are occupied with reference materials,  
**So that** I can write articles without switching between typing and reading.

**As a** developer,  
**I want to** quickly dictate code comments or documentation,  
**So that** I can maintain flow state without context switching to a text editor.

**As a** non-native speaker,  
**I want to** use voice input to practice pronunciation while getting immediate text feedback,  
**So that** I can improve my language skills during daily computer use.

## 4. Functional Requirements

### 4.1 Hotkey & Activation System
- **FR-1.1:** Support configurable modifier key activation (default: Option/Alt key)
- **FR-1.2:** Implement press-and-hold paradigm: key down = start recording, key up = stop & process
- **FR-1.3:** Global event monitoring functional even when app is not key window
- **FR-1.4:** Visual feedback within 100ms of key press (window appears)

### 4.2 Recording Interface (State: Recording)
- **FR-2.1:** Display floating panel centered on active screen
- **FR-2.2:** Real-time audio waveform visualization (60fps animation)
- **FR-2.3:** Visual indicator showing audio input levels (amplitude-based)
- **FR-2.4:** "Close" button for manual cancellation
- **FR-2.5:** Maximum recording duration: 60 seconds (auto-stop with warning)

### 4.3 Transcription & Processing
- **FR-3.1:** Audio format: 16kHz, 16-bit, mono PCM or Opus compression
- **FR-3.2:** Support multiple providers: OpenAI Whisper API (cloud) or whisper.cpp (local)
- **FR-3.3:** Primary/Fallback model configuration (e.g., try large-v3 first, fallback to base if timeout)
- **FR-3.4:** Network timeout handling with automatic retry (max 2 attempts)
- **FR-3.5:** Local caching of audio files until transcription is confirmed successful

### 4.4 Result Interface (State: Transcription Complete)
- **FR-4.1:** Display transcribed text in editable text field
- **FR-4.2:** Auto-copy to system clipboard immediately upon receipt
- **FR-4.3:** Three action buttons:
  - "Clear": Dismiss without action, delete audio cache
  - "Copy": Copy to clipboard (redundant but explicit)
  - "Insert": Simulate Command+V keystroke to active application
- **FR-4.4:** Auto-dismiss timeout: 10 seconds if no user interaction (configurable)

### 4.5 Settings & Configuration
- **FR-5.1:** General Settings:
  - Hotkey configuration (modifier keys only or custom combo)
  - Auto-paste behavior (on/off)
  - Auto-dismiss timeout duration
  
- **FR-5.2:** Model Configuration:
  - API Key and Endpoint URL (encrypted storage in Keychain)
  - Model selection: tiny, base, small, medium, large-v1/v2/v3
  - Language specification (auto-detect or forced)
  
- **FR-5.3:** Fallback Strategy:
  - Primary model selection
  - Fallback model selection (triggered on timeout or 5xx errors)
  - Local model path configuration (for whisper.cpp integration)

### 4.6 Error Handling & Edge Cases
- **FR-6.1:** Microphone permission denial: Graceful error message with System Preferences link
- **FR-6.2:** Network connectivity loss: Queue transcription for retry, local backup
- **FR-6.3:** API rate limiting: Exponential backoff, fallback model activation
- **FR-6.4:** Insufficient audio volume: Warning after 3 seconds of silence
- **FR-6.5:** Audio device unavailable: Automatic device enumeration and selection

## 5. Technical Requirements

### 5.1 Architecture Stack
- **Language:** Swift 5.9+
- **UI Framework:** SwiftUI (primary), AppKit (window management integration)
- **Minimum OS:** macOS 13.0 (Ventura)
- **Architecture:** ARM64 (Apple Silicon optimized, x86_64 compatibility not required)

### 5.2 Key Frameworks
- `AVFoundation`: Audio capture and metering
- `Carbon` or `NSEvent`: Global hotkey monitoring (`CGEventTap` or `NSEvent.globalMonitor`)
- `Combine`: Reactive state management for recording -&gt; processing -&gt; result flow
- `Security` & `LocalAuthentication`: API key storage in Keychain
- `CoreGraphics`: Event simulation for auto-paste functionality

### 5.3 Performance Specifications
- **Memory:** &lt; 200MB RAM usage during active recording
- **CPU:** Audio processing &lt; 10% CPU on M1 Pro during recording
- **Latency:** Window appearance &lt; 100ms from key press
- **Disk:** Temporary audio storage &lt; 10MB per recording session (auto-cleanup)

### 5.4 Security & Privacy
- **SEC-1:** API credentials stored exclusively in macOS Keychain, never in UserDefaults
- **SEC-2:** Audio data encrypted at rest during processing (FileProtection complete)
- **SEC-3:** No persistent storage of transcribed text (memory-only unless user saves)
- **SEC-4:** Microphone indicator (orange dot) compliance with macOS privacy standards
- **SEC-5:** Optional: On-device transcription mode for sensitive environments (no cloud)

## 6. UI/UX Specifications

### 6.1 Visual Design
- **Style:** Native macOS aesthetic, minimal chrome
- **Background:** Material blur (NSVisualEffectView) with .hud or .popover appearance
- **Colors:** System accent colors for waveform, neutral grays for chrome
- **Typography:** San Francisco (system font), dynamic type support

### 6.2 Interface States

**State 1: Idle (Hidden)**
- No visible UI
- Global hotkey listener active

**State 2: Recording** *(Reference: Image 1)*
- Floating panel: 300x120px, centered
- Central waveform visualization (bars or line graph)
- Subtitle: "Listening..." or audio level meter
- Cancel button (X) top-right

**State 3: Processing**
- Same window dimensions
- Activity indicator (progress bar or spinner)
- Status text: "Transcribing..." with elapsed time

**State 4: Result** *(Reference: Image 2)*
- Expanded window: 400x150px
- Text preview area (scrollable if &gt; 3 lines)
- Action bar: [Clear] [Copy] [Insert ↵]
- Insert button uses system blue accent (primary action)

### 6.3 Accessibility
- **A11Y-1:** VoiceOver support for all UI elements
- **A11Y-2:** High contrast mode support
- **A11Y-3:** Reduce motion support (disable waveform animation)
- **A11Y-4:** Keyboard navigation support in result window (Tab to switch actions, Enter to confirm)

## 7. Non-Functional Requirements

### 7.1 Distribution
- **Method:** Developer ID signed (outside Mac App Store) due to sandboxing limitations with global hotkeys and event simulation
- **Notarization:** Required for Gatekeeper compliance
- **Updates:** Sparkle framework integration for OTA updates

### 7.2 Internationalization
- **Phase 1:** English (en), Simplified Chinese (zh-Hans)
- **Phase 2:** Japanese (ja), Korean (ko), German (de)
- **UI:** All strings externalized in Localizable.strings
- **Transcription:** Support for multilingual transcription (Whisper supports 99 languages)

### 7.3 Testing Requirements
- **Unit Tests:** Audio processing logic, API client retry mechanisms
- **Integration Tests:** End-to-end hotkey -&gt; recording -&gt; clipboard flow
- **Device Testing:** M1, M1 Pro, M1 Max, M2, M3 series compatibility
- **Accessibility Testing:** VoiceOver navigation validation

## 8. Open Questions & Future Considerations

1. **Local Model Bundling:** Should we bundle a quantized tiny model (75MB) for offline capability, or require user download?
2. **Continuous Dictation:** Future support for "push-to-talk" mode vs. current "hold-to-talk"?
3. **Text Formatting:** Automatic punctuation insertion vs. literal transcription ("comma" vs. ",")?
4. **Plugin System:** Allow custom post-processing scripts (e.g., auto-format code, capitalize titles)?
5. **Analytics:** Opt-in telemetry for tracking transcription success rates and latency metrics?
